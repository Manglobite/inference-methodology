# Методология: индекс каталога

Каталог `methodology/` содержит переносимую методику исследований локального
инференса LLM и шаблон публикуемого исследования. Он лежит внутри узла, но его
основные документы рассчитаны на переиспользование на другом стенде.

## Документы

| Документ | Назначение |
| --- | --- |
| [METHODOLOGY.md](METHODOLOGY.md) | **Портируемая методология**: инварианты, оси эксперимента, лесенка/A-B, метрики, телеметрия, агрегация и графики, портируемость. Не привязана к конкретному железу. Перевод: [METHODOLOGY.en.md](METHODOLOGY.en.md). |
| [hardware_info/HARDWARE.md](hardware_info/HARDWARE.md) | **Описание конкретного стенда** этого узла (GPU, CPU, диск, драйвер, тулчейн) и матрица параметров. НЕ предназначен для внешней публикации: содержит конфигурацию узла. Индекс — [hardware_info/README.md](hardware_info/README.md). |
| [TEMPLATE.md](TEMPLATE.md) | **Шаблон публикуемого исследования**: обязательный состав, структура каталога, форматы профилей/промптов/прогонов/агрегатов, барьер публикации, адаптация. Перевод: [TEMPLATE.en.md](TEMPLATE.en.md). Рабочий скелет — [templates/research-case/](templates/research-case/), пример конфига агрегаторов — [templates/research-case/study.example.json](templates/research-case/study.example.json). |

## Быстрый старт: новое исследование

1. Прочитайте [METHODOLOGY.md](METHODOLOGY.md) — это общий протокол измерений
   (что фиксировать, как строить лесенку, какие метрики и графики обязательны).
2. Скопируйте скелет:
   `cp -r templates/research-case/ ../<новый-кейс>/` и следуйте
   [TEMPLATE.md](TEMPLATE.md), раздел «Как адаптировать шаблон».
3. Скопируйте нужные переносимые скрипты из `scripts/<категория>/` в
   `<кейс>/scripts/` (пример — в [scripts/README.md](scripts/README.md)) и
   скопируйте `templates/research-case/study.example.json` в `<кейс>/study.json`,
   заменив плейсхолдеры (без `study.json` агрегаторы автоопределяют профили,
   подписи, порядки и ступени из сырых прогонов).
4. Загляните в [hardware_info/HARDWARE.md](hardware_info/HARDWARE.md), если
   нужно спланировать раскладку параметров под этот конкретный узел (матрица
   параметров и наблюдаемые эффекты).

Порядок адаптации: заполнить документы и профили, скопировать нужные скрипты из
[scripts/](scripts/README.md) в `<кейс>/scripts/`
(см. `templates/research-case/scripts/README.md`), затем пройти
`templates/research-case/CHECKLIST.md`.

## Скрипты

Переносимые версии скриптов методологии лежат в [scripts/](scripts/README.md) по
категориям: [runner/](scripts/runner/), [telemetry/](scripts/telemetry/),
[report/](scripts/report/), [publish/](scripts/publish/). Они не привязаны к
железу и кейсу и копируются в каталог исследования.

## Публикация

- **METHODOLOGY.md** и **TEMPLATE.md** — переносимы; при публикации отдельным
  репозиторием их можно включать в публикацию (ссылки между документами
  относительные, при переносе замените на стабильный URL/commit).
- **hardware_info/HARDWARE.md** описывает **конкретный узел** и для внешней
  публикации не предназначен: при публикации кейса используйте его локальную
  копию `HARDWARE.md` внутри каталога кейса, а не этот файл.
